# CONTEXT — sre-on-call

Domain vocabulary for the project. Use these terms consistently in code, docs, and conversation.

## Domain Terms

**AlertContext** — The structured context extracted from a chat alert message (platform, channel, timestamp, investigation window). Passed through the entire investigation pipeline. Defined in `shared/models.py`.

**Finding** — A single piece of evidence discovered by an agent during investigation. Has source, timestamp, content, severity, and metadata. Defined in `shared/models.py`.

**AgentResult** — The canonical result returned by a specialized agent to the Master Agent via A2A protocol. Contains agent name, status (`success` | `error` | `unhealthy`), findings, and summary. `error` is request-level failure (transient — recommended action is "retry / manually check"). `unhealthy` indicates the agent fundamentally cannot do work in this deployment (operator-actionable — recommended action is "investigate agent configuration"). Defined in `shared/models.py`.

**ToolResult** — The generic intermediate result produced by any agent tool's `_execute_*()` function. Contains `findings`, `scanned_items` (flat list, prefixed for multi-category agents e.g. `pod/name`, `node/name`), and `errors`. Converted to `AgentResult` via `build_agent_result()`. Defined in `shared/tool_result.py`.

**AgentFooter** — A literal-marker-delimited JSON block appended to the end of an agent's A2A text response, used to round-trip a structured payload (`AgentResult`, `SnapshotReport`, `AgentMetadata`) through the LLM's text channel. The marker pair (`<<<KIND … KIND>>>`) is the discriminator; the body is `json.dumps(asdict(payload))`. Permissive on read — malformed JSON, missing required keys, and unknown fields are silently dropped because the footer is transport telemetry, not load-bearing data. The seam is `AgentFooter[T]` in `shared/agent_footer.py`, parametrised by a parser callable; concrete instances (`AGENT_RESULT`, `SNAPSHOT_RESULT`, `AGENT_METADATA`) live alongside their dataclasses in the modules that own them. Distinct from the **A2A envelope** (the JSON-RPC 2.0 `message/send` request, defined in `shared/a2a_protocol.py`) — the footer rides inside the envelope's text part.

**A2AClient** — The seam for a single A2A round-trip to one specialized **Agent**. `A2AClient(http_client)` wraps an injected `AsyncHTTPClient` transport adapter (`AiohttpClient` for local URLs, `AgentCoreClient` for `arn:` runtime endpoints); `send(endpoint, text, *, footer, request_id) -> A2AReply[T]` builds the **A2A envelope** (`build_a2a_request`), POSTs it via the transport, surfaces a JSON-RPC error, extracts the canonical reply text (`extract_response_text`), and parses the one caller-supplied `AgentFooter[T]`. The seam knows the A2A wire format and nothing about `AgentResult` / `SnapshotReport` semantics — the caller picks which footer to expect and maps the reply to its own domain type. The **Fanout** constructs one client over a `RoutingHTTPClient` transport that routes each call per endpoint (ARN → `AgentCoreClient`, URL → `AiohttpClient`), so a mixed deployment dispatches every agent correctly; `.send()` is called per agent. Lives in `shared/a2a_client.py` alongside the transport adapters — including `RoutingHTTPClient` (moved out of the orchestrator). Sits above `shared/a2a_protocol.py`, which stays a pure, dependency-free envelope builder + text extractor.

**A2AReply** — The neutral result of one `A2AClient.send()`, generic over the footer payload type `T`: `text` (the agent's reply with the footer stripped), `payload` (`T | None` — the parsed footer; `None` when absent or malformed, since footers are permissive on read), and `error` (`str | None` — the JSON-RPC `error.message` when the agent returned a protocol-level error). A JSON-RPC error is a *value* on the reply, not an exception; transport/network failures still raise out of `send()`. Callers branch on `error` and map to their domain type — the alert path to `AgentResult(status="error")`, the status path to a raised `RuntimeError`. Defined in `shared/a2a_client.py`.

**StructuredModelCall** — The seam for one bounded, structured-output model call made outside any planner loop (the master's routing / synthesis / follow-up decisions, the offline experiment judge). Owns the interface burden its call sites used to repeat per-site: the gate flag (`from_env(gate_env=…)` → `None` when disabled), model resolution (per-call env override → `MODEL_ID` → config/default via `_resolve_model`, so `BEDROCK_GUARDRAIL_ID` applies), timeout parsing, the lazy tools-less Strands `Agent` build, optional pinned temperature, and the non-deprecated invocation surface (`invoke_async(prompt, structured_output_model=…)`). Two error modes: `call(output_model, prompt)` is **fail-open** — any error, timeout, or build failure returns `None` and the caller proceeds without the result; `call_or_raise(…)` propagates, for callers that own their own failure policy (the judge CLI fails per-pair). Every call records token usage into a request-scoped accumulator (the `log_summarizer` pattern) that the `InvestigationOrchestrator` drains into the experiment scorecard, so master-side decision cost is counted alongside agent cost. `AgentRouter`, `AnalysisSynthesizer`, `FollowupPlanner`, and `ExperimentJudge` compose one instance each and keep only their prompt builder, response validation, and domain types; tests inject a fake `StructuredModelCall` instead of per-site `agent=` fakes. Not for the raw-boto3 tier (`BedrockLlmClassifier`, `BedrockLogSummarizer`, `EmbeddingClient`) — sync Lambda and threadpool contexts where a Strands agent doesn't fit. Defined in `shared/model_call.py`.

**IncidentFacts** — The canonical, deterministically-derived view of one investigation's results, built **exactly once per report build** by `IncidentFacts.derive(registry, alert_context, agent_results, *, pending, disabled, skipped)` and projected into every outbound surface. Carries severity, affected services, per-agent summary/root-cause parts, the **five-state per-agent evidence** (`EvidenceFact` with `ok|error|pending|disabled|skipped`, one walk in registry render order), the `IncidentTimeline`, chart-id references, impact/recommended-actions/links, and the telemetry totals line. Facts only — derived from `AgentResult`s, the alert, and the **Agent registry**; never LLM output (the #27 Analysis rides alongside a projection, not inside the facts). Re-derived on each enrichment arrival, since facts are a function of the current result set, not an accumulator. `ReportFormatter` keeps the registry and shrinks to thin projections: `build_incident_sections` → `ReportSections`, `build_page_model` → `PageModel` (full five-state mirror — fixes the prior bug where the interactive page emitted only `ok` blocks and silently dropped failed/pending/disabled/skipped agents the chat report surfaces), `build_pir_sections` → `PIRSections` (its timeline is `render_pir_timeline_markdown(facts.timeline)`; the old second-walk `_build_pir_timeline` is deleted), and `build_timeline` → `facts.timeline` for the trace manifest. `build_enrichment_sections` stays separate — it formats a single late `AgentResult`, not a walk over the result set. Defined in `agents/master/incident_facts.py`.

**Fanout** — The seam for dispatching an A2A request to every active specialized **Agent** and harvesting the replies under a caller-controlled deadline. Constructed from the **Agent registry**: resolves each active specialized agent's endpoint, builds one `A2AClient` over a per-endpoint `RoutingHTTPClient`, and exposes the ordered active agents plus the disabled-in-config set. `dispatch(make_coro)` spawns one task per active agent from a caller-supplied per-agent coroutine and returns the pending `{agent_id: Task}` map; `harvest(pending, timeout) -> (settled, still_pending)` waits up to `timeout`, returns the completed results keyed by agent id (a raised exception is handed back as a value, not propagated) and the tasks still in flight; `cancel(pending)` drains the leftovers. Generic over the per-agent result type and blind to footers, trace, and `AgentResult` / `SnapshotReport` semantics — the caller's coroutine owns `send`, the `AgentFooter` choice, the reply→domain mapping, and any trace events. A second harvest re-waits the same in-flight requests (no re-invocation): the `InvestigationOrchestrator` harvests at the 60 s initial deadline, then in late-enrichment windows to the 5-min cutoff; the `StatusSnapshotOrchestrator` harvests once at 30 s. Lives in `shared/fanout.py`, above `shared/a2a_client.py`. Subsumes the endpoint-resolution + transport-selection + per-agent task bookkeeping that was duplicated inline in both orchestrators.

**MasterDispatch** — The seam for firing one fire-and-forget task at the **Master Agent** runtime from the Lambda intake pipeline. A Protocol with one typed method per task kind — `investigate(alert_context, *, master_arn=None)`, `postmortem(command)`, `status(command, requested_at)` — each owning its `runtimeSessionId` convention (`investigation_id`, with a `-{variant_id}` suffix when the context carries one; `pir-{channel_id}-{thread_ts}`; `snapshot-{channel_id}-{requested_at}`), its A2A **envelope** build (`build_a2a_request`), and `MASTER_AGENT_RUNTIME_ARN` resolution (overridable per-variant via `master_arn`). `AgentCoreMasterDispatch` is the production adapter (synchronous `bedrock-agentcore.invoke_agent_runtime`; the response is discarded — the master posts its own "Investigation Started" notice); `RecordingMasterDispatch` is the test adapter, capturing dispatched tasks as values. Injected into `process_webhook(event, platform, dispatch)` exactly as `ChatPlatform` is, so intake tests assert on dispatched tasks rather than patching boto3. Distinct from `A2AClient`, which does a round-trip to one specialized **Agent** and reads a reply — `MasterDispatch` fires one task at the master and reads nothing. Experiment variant fan-out stays in the intake pipeline; the dispatch only receives the per-variant ARN. Lives in `lambda_adapter/master_dispatch.py`.

**WebhookEvent** — A tagged union returned by `ChatPlatform.ingest()`. One of `InvalidWebhook(status_code, reason)`, `ChallengeWebhook(response)`, `AlertWebhook(context)`, or `CommandWebhook(command)`. The intake pipeline pattern-matches on the variant. Defined in `shared/platforms/__init__.py`.

**ChatPlatform** — The seam between the investigation pipeline and a chat platform. Protocol with 4 methods: `ingest(headers, raw_body) -> WebhookEvent` (verify signature, classify the request), `ack(command, text)` (synchronous slash-command callback), `notice(target, text)` (synchronous plain-text reply — used by the **Alert classification** gate to nudge non-alert mentions without a slash-command `response_url` or a structured payload; fail-open), and `async deliver(alert_context, payload) -> str` (render `ReportSections` / `EnrichmentSections` / `InvestigationStartedSections` / `PIRSections` to platform-native markup, post it as a thread reply, return the rendered text). Slack and Discord each provide one implementation in `shared/platforms/`. Subsumes the legacy `WebhookAdapter` + `ChatPoster` + `ReportRenderer` seams.

**Alert classification** — The intake gate that decides whether a new mention is an operational alert worth investigating before the **MasterDispatch** fan-out. Two tiers in `lambda_adapter/classifier.py`: Tier 1 `classify_heuristic` (pure, deterministic — severity keywords, Alertmanager/Grafana formatting markers, dashboard/console links on the alert side; greetings/acknowledgements/empty/short on the chatter side; returns `None` when ambiguous), and an optional Tier 2 `LlmClassifier` seam (`BedrockLlmClassifier` — one synchronous Bedrock Converse turn, gated on `CLASSIFIER_LLM_ENABLED`). `classify_alert(text, llm=…)` combines them and is **fail-open**: an ambiguous Tier 1, a `None`/absent LLM, or any error all default to `is_alert=True` (investigate), so a real page is never dropped. The `investigate` keyword is a manual override that forces an alert. Wired into `_process_alert` (after dedup, before dispatch) behind `ALERT_CLASSIFICATION_ENABLED` (default on); a gated mention gets a `ChatPlatform.notice` reply and no dispatch. A `Classification(is_alert, tier, reason)` records which stage decided.

**DeliveryTarget** — The routing-only value a `ChatPlatform.deliver(target, payload)` call posts to: `platform` (`slack` | `discord`), `channel_id`, and `thread_anchor` (`str | None` — the originating message id to reply under; `None` posts at top-level). Each platform interprets `thread_anchor` natively (Slack `thread_ts`, Discord `message_reference.message_id`). `DeliveryTarget.for_alert(alert_context)` projects an **AlertContext** down to its routing fields (anchor = the alert's `message_id`); the `/sre-snapshot` path builds a top-level target (`thread_anchor=None`) directly. Replaces the prior practice of passing a whole `AlertContext` — real for alerts, synthetic for `/sre-snapshot` — to `deliver`, and the `message_id=""` sentinel that meant "post at top-level." Defined in `shared/platforms/__init__.py`.

**ChannelMessageSource** — The seam between the shared channel-scanning algorithm and a chat platform. Protocol with 3 methods (`fetch_messages`, `is_alert`, `extract_finding`). Slack and Discord each provide an adapter (`SlackMessageSource`, `DiscordMessageSource`). The scanning algorithm (`execute_channel_scan`) lives in `shared/channel_scan.py` and is parameterized by a source. Defined in `shared/channel_scan.py`.

**Agent** — A runtime in the project (the master orchestrator or one of the specialized agents). Each Agent has a stable identity (id, display name, emoji, render order), a kind (`orchestrator` | `specialized`), and wiring (runtime-ARN env-var key, local-URL env-var key, default local URL). Resolved through the **Agent registry**. The `agents:` block in `config.yaml` is the *deployment manifest* — its keys must be known agent ids; an `enabled: false` flag marks an agent as deployed-but-inactive (built and pushed to ECR, but the orchestrator skips it on fan-out and surfaces it as a 🚫 disabled evidence block).

**Agent registry** — The single source of truth for "what agents exist and what's their state in this deployment." Code-side records (`shared/agents.py`) are folded with the `agents:` block from `config.yaml` at load time. Exposes `all()` (catalogue, used by config validation), `deployed()` (listed in `config.yaml`, used by terraform / build), `active()` (deployed AND `enabled=True`, used by orchestrator fan-out), `disabled_in_config()` (deployed AND `enabled=False`, used by the formatter to render 🚫 disabled evidence blocks), and `lookup(id)`. Each method takes an optional `kind` filter. Replaces the constants `KNOWN_AGENTS`, `DEFAULT_AGENT_ENDPOINTS`, `_ENV_KEYS`, `_RUNTIME_ARN_ENV_KEYS`, `AGENT_DISPLAY`, `AGENT_ORDER`, and the `ENABLED_AGENTS` env var.

**SnapshotReport** — A specialized agent's read-only snapshot of its observed infrastructure, returned by the agent's `capture_snapshot` tool in response to the `/sre-snapshot` slash command. Carries the agent's name, the wall-clock instant the snapshot was taken, a list of labelled `SnapshotSection`s (each a pre-rendered bullet list), and an `anomaly` flag with an optional one-line `anomaly_summary` the master uses for the deterministic top-line summary. Contrasts with `AgentResult` (alert-correlation findings); a snapshot is descriptive, not investigative. Defined in `shared/models.py`.

**SnapshotSections** — The platform-agnostic deliver payload for `/sre-snapshot` output. Built by the master's `StatusSnapshotOrchestrator` from per-agent `SnapshotReport`s plus a registry view, and rendered by each platform's `MarkupReportRenderer.render_snapshot()` into native markup. Contains a `requested_at` timestamp, the deterministic `summary_line`, and a list of `SnapshotBlock`s (one per agent — each with emoji, display name, registry-derived header line, content sections, and a four-state status marker `ok` / `anomaly` / `error` / `disabled`). Sibling to `ReportSections`, `EnrichmentSections`, `InvestigationStartedSections`, `PIRSections` in the `DeliverPayload` union. Defined in `shared/report_renderer.py`.

**StatusSnapshotOrchestrator** — The master agent's engine for the `/sre-snapshot` slash command. Distinct from `InvestigationOrchestrator` (alert path): single 30-second hard cutoff with no late-enrichment phase, builds the master's own block synchronously via `MasterSnapshotBuilder` (no fan-out for itself), fans out a snapshot-shaped A2A request `{"task": "snapshot", "requested_at": <ISO>}` to every active specialized agent, extracts each agent's `SnapshotReport` from the `<<<SNAPSHOT_RESULT ... SNAPSHOT_RESULT>>>` footer, and posts a `SnapshotSections` payload at top-level (not as a thread reply) via a synthetic `AlertContext` with `message_id=""`. Defined in `agents/master/snapshot_orchestrator.py`.

## Conventions

- Agent tool files follow the pattern: `@tool` entry point → `_execute_*()` → `build_agent_result()` → `format_result()`.
- `@tool` entry points own I/O client creation (boto3 clients, K8s API clients, SDK clients) and pass them into `_execute_*()`.
- `_execute_*()` receives its I/O clients as required parameters and contains no client construction. This is the test surface — tests call `_execute_*()` directly with mock clients, no patching needed.
- `_execute_*()` returns a `ToolResult`. Platform-specific investigation logic lives here.
- `build_agent_result()` and `format_result()` are shared — do not duplicate in tool files.
- `severity_from_text()` is the shared text-based severity heuristic (critical/fatal → critical, error/exception/failure → warning, else info). Domain-specific severity functions (e.g. `_severity_from_phase` for Kubernetes pod phases) stay local to their agent.
- `scanned_items` uses prefixed strings when an agent inspects multiple resource types (e.g. `pod/nginx-abc`, `node/ip-10-0-1-5`).
